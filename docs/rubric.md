# デザイン評価ルーブリック

Evaluator はこのファイルのアンカーに従って採点する。
**印象で点をつけてはならない。** 各スコアには、どのアンカーに該当したかを引用して根拠を書く。

アンカーが無い採点は再現しない。同じ画面を2回評価して点が変わるなら、それは評価ではなく感想である。

## 合格条件

以下の**両方**を満たしたときのみデザイン評価は合格：

1. 4基準すべてが個別の閾値以上
2. 加重総合スコア ≥ 6.0

```
加重総合 = デザインの質 × 0.35
         + オリジナリティ × 0.35
         + クラフト × 0.15
         + 機能性 × 0.15
```

| 基準 | 閾値 | 重み |
|------|------|------|
| デザインの質 | 6/10 | 0.35 |
| オリジナリティ | 6/10 | 0.35 |
| クラフト | 5/10 | 0.15 |
| 機能性 | 7/10 | 0.15 |

---

## 1. デザインの質（閾値 6 / 重み 0.35）

視覚的ヒエラルキー、タイポグラフィ、余白、色使いの完成度。

| スコア | アンカー |
|--------|----------|
| **9-10** | 情報階層が一目で読める。タイポグラフィのスケールが3段階以上明確に効いている。余白が `--space-*` スケールに完全に整合。色数が抑制され、意味を持って使われている。初見のユーザーが「次に何をすべきか」を迷わない |
| **7-8** | 階層は明確。タイポと余白はトークン準拠。1〜2箇所に詰めの甘さ（同種要素の余白が ±4px ずれる等）がある |
| **6** | トークンには準拠している。階層はあるが弱い（サイズ差はあるがウェイト・色で補強されていない）。合格の下限 |
| **4-5** | トークン外の色・フォントサイズが混在。または視覚的ヒエラルキーが無く、全要素が同じ重さで並んでいる |
| **2-3** | フレームワークのデフォルトスタイルがほぼそのまま。余白が場当たり的 |
| **0-1** | 未スタイル同然。ブラウザ標準の見た目 |

**減点トリガー（該当したら上のバンドから1点引く）**
- 同種の要素（カード、ボタン、セクション）で余白が 4px 以上ばらつく
- 見出しと本文が同じフォントサイズ
- テキストと背景のコントラスト比が 4.5:1 未満（`browser_evaluate` で計測可能）
- 1画面に5色以上のアクセントカラー

---

## 2. オリジナリティ（閾値 6 / 重み 0.35）

「AIが生成したテンプレート」に見えないか。参考画像の方向性が反映されているか。

| スコア | アンカー |
|--------|----------|
| **9-10** | レイアウトに固有の判断がある（非対称グリッド、意図的な余白の抜き、特徴的なタイポ処理など）。参考画像のトーンが明確に反映されている。他のプロダクトと差し替えが効かない |
| **7-8** | 定型から外れた工夫が2箇所以上ある。セクションごとにリズムの変化がある。スロップ兆候 0〜1件 |
| **6** | 無難だが定型ではない。スロップ兆候1件以下。合格の下限 |
| **4-5** | スロップ兆候2件。どこかで見たテンプレートに見える |
| **0-3** | スロップ兆候3件以上（**自動的にこのバンド**）。生成AIのデフォルト出力と区別がつかない |

### AIスロップ兆候チェックリスト

**3件以上該当した場合、オリジナリティは自動的に 4/10 以下にする。**

- [ ] 白背景に紫/青のグラデーション（`linear-gradient` で purple → blue 系）
- [ ] 角丸カードの均等グリッド（同じ幅・同じ余白のカードが3つ以上横並び）が主要レイアウト
- [ ] 意味を持たないストックアイコンの羅列（機能を説明していない装飾アイコン）
- [ ] 装飾目的のグラデーション（情報の区別に寄与しないもの）
- [ ] 全セクションが「見出し + 本文 + カード群」の同一構造の繰り返し
- [ ] Hero セクションが「特大見出し + サブテキスト + CTA 2つ」の定型
- [ ] 参考画像が `docs/design-references/` にあるのに、トーンが一切反映されていない

## 3. クラフト（閾値 5 / 重み 0.15）

細部の作り込み。状態表現、遷移、端の処理。

| スコア | アンカー |
|--------|----------|
| **9-10** | 全インタラクティブ要素に hover / focus / active / disabled が定義。ローディング・空・エラー状態が全て設計済み。トランジションが `--duration-*` で統一 |
| **7-8** | hover と focus は全要素に。空状態とローディングが設計済み。1〜2箇所の状態が未定義 |
| **5-6** | hover は付いている。focus リングが残っている（`outline: none` で潰していない）。合格の下限 |
| **3-4** | 状態表現がほぼ無い。またはフォーカスリングを消して代替を用意していない |
| **0-2** | クリックできる要素とできない要素が見分けられない |

**減点トリガー**
- `outline: none` で代替フォーカス表示なし（アクセシビリティ違反。**即座に 3 以下**）
- 空状態（データ0件）で真っ白または壊れた表示
- ローディング中に画面がガタつく（レイアウトシフト）

---

## 4. 機能性（閾値 7 / 重み 0.15）

デザイン適用後もアプリが機能するか。レスポンシブ。

| スコア | アンカー |
|--------|----------|
| **9-10** | `npm run e2e` 全件緑。375 / 768 / 1280 px すべてで崩れなし。コンソールエラー0件 |
| **8** | E2E 全件緑。3幅すべて崩れなし。軽微なコンソール警告あり |
| **7** | E2E 全件緑。3幅で崩れなし。合格の下限 |
| **4-6** | いずれかの幅で横スクロールが発生、要素が重なる、テキストが切れる |
| **0-3** | デザイン適用で機能が壊れた（E2E が赤）。**この場合は無条件で不合格、@agent-designer に差し戻し** |

**必須実測（Designer の自己申告を根拠にしてはならない）**
- `browser_resize` で 375 / 768 / 1280 px を実際に開いてスクリーンショットを撮る
- `browser_console_messages` でエラーを確認する
- `npm run e2e` を実行する
