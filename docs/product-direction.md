# 製品の方向 —— 決定の台帳

> **Planner が書く、手で書く文書**（生成物ではない）。`docs/spec.md` は計画の時点の仕様で、
> スプリントを重ねるうちに下された**方向の決定**（ユーザーの答え・実機の指摘から生まれた変更）はここに積む。
>
> **この文書は追記のみ。** 既存の行・節は1字も書き換えない。変えたいときは、新しい決定を足して古い決定を名指しで覆す。
> 理由: 書き換えると「いつから・なぜ変わったか」と「その時点のテストが何を守っていたか」が追えなくなる。

## 書き方の決まり

| 決まり | 中身 |
|---|---|
| **ID** | 決定には `V-<連番>` を振る。番号は**実在の最大 + 1**。採る前に `grep -rhoE "V-[0-9]+" docs \| sort -u` で実在を数える |
| **追記のみ** | 新しい決定は末尾に「追記N」の節を立てて足す。既存の節は書き換えない |
| **覆すときは名指す** | 新しい決定が古い決定を取り消すなら、「覆す」欄に古い ID を書く（supersedes）。半分だけ覆すなら、どちらの半分かを書く |
| **生きるものも名指す** | 覆さずに残る決定を「生きる」欄に書く（読み手が「全部変わった」と誤読しないため） |
| **失うものを隠さない** | その決定で失われるもの（体験・安心・既存の約束）を1〜3行で書く |
| **出どころ** | ユーザーの答え／実機の指摘／Planner の既定 のどれか。ユーザーの答えなら `status.md` の節を指す |
| **テストへの波及** | 既存のテストを覆す決定は、その回の契約の **R 表**（付け替えの見込み）に先に並べる |
| **幽霊を作らない** | まだ存在しない ID（範囲・予告・例）を `V-` の形で書かない。「次は 12 番から」のように接頭辞なしで書く |
| **別のコミット** | 決定の追記は、契約とは別のコミットで書く（どちらを戻しても他方が残るように） |

---

## §1. 決定（初版）

| ID | 決定 | 種類 | 出どころ |
|---|---|---|---|
| （最初の決定を 1 番で書く） | （例: 主語はペットである。人は「撮った人」として残る） | 方向 | ユーザーの答え（`status.md` の節名） |

> この雛形は `V-` に数字を付けた ID を1つも含まない（例の ID を数字で書くと、実在の決定として数えられてしまう）。

## 追記の雛形（コピーして末尾に足す）

```markdown
### 追記N —— `V-a` <決定の要約> ・ `V-b` <決定の要約>（YYYY-MM-DD ・ <出どころ> ・ **この追記より上は書き換えない**）

**出どころ**: `docs/sprints/status.md` の「<節名>」（オーケストレーターの記録。Planner は原文を直に聞いていない）
**立てた回**: Sprint N（`docs/sprints/sprint-N/contract.md` の §M）

| 番号 | 決定 | 立てた回 | 出どころ |
|---|---|---|---|
| `V-a` | ... | Sprint N | ユーザーの答え「...」 |

覆す      V-x（<古い決定の要約>）→ V-a
          V-y の半分（<どちらの半分か>）→ V-b
生きる    V-z（<なぜ残るか>）
将来      （送りの ID）

**失うもの**: ...

**テストへの波及**: Sprint N の契約の R 表 R1〜R5（付け替え 4本 ・ 変わらず緑 1本）
```
