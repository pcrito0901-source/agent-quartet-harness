Sprint $1 のデザインに、ユーザーの手直しを入れます。

これは Evaluator が**合格を出した後**に回す、人間のためのレビュー枠です。
デザインの良し悪しを最終的に決めるのはルーブリックではなくユーザーであり、
`/sprint` のループにはその入口がありません。それを補うのがこのコマンドです。

## 手順

### 1. 現状を見せる

`docs/runbook.md` のとおりに開発サーバーを起動し、Playwright MCP で主要画面の
スクリーンショットを撮ってユーザーに提示する。375 / 1280px の2幅を見せる。

### 2. 指摘を受ける

引数に指摘が含まれていればそれを使う。無ければ `AskUserQuestion` で聞く。

**「特に無い」という答えなら、何もせずに終了する。** 手を入れないことも正しい結果である。

### 3. Designer に渡す

`@agent-designer` を起動し、以下を渡す:

- 対象スプリント番号と `docs/sprints/sprint-$1/designer-report.md` のパス
- **ユーザーの指摘をそのままの言葉で**（要約して抽象化しない。「余白が狭い」を
  「スペーシングの調整」に言い換えると、意図が失われる）
- 指摘の種類に応じた行き先の指示:
  - **値の話**（余白・色・サイズ）→ `docs/design-tokens.css` を直す。以降の全スプリントに効く
  - **判断の話**（方針・禁止事項）→ Designer の記憶に残す（`memory: project` が設定済み）

### 4. 非破壊を確認する

```
npm run e2e
```

**Evaluator を丸ごと回す必要はありません。** 契約は既に実行可能なテストになっているため、
E2E スイートが緑であれば「機能を壊していないこと」は証明されます。数秒で終わります。

赤くなった場合は Designer に差し戻す。3回繰り返しても直らなければ、
ユーザーに「その変更は機能と両立しない可能性がある」と報告して判断を仰ぐ。

### 5. 記録して締める

- Designer に `designer-report.md` の末尾へ「ユーザーによる手直し」節を追記させる
- `git commit -m "sprint-$1: polish"`
- ユーザーに再度スクリーンショットを提示し、これでよいか確認する
- まだ直したい箇所があれば 2 に戻る

## 注意

- **オーケストレーターが直接CSSを触らないこと。** Designer に委譲する。
  ここを崩すと、変更が `designer-report.md` にも記憶にも残らず、次スプリントで元に戻る
- トークンで解決できる指摘を、その場のCSSで直さないこと。**同じ指摘を次のスプリントでも
  受けることになる**
